# Apex Horizon — Unreal Engine 5.8

The same open-world arcade-sim racer as the browser build in this repository's root,
rebuilt on Unreal Engine 5.8: same circuit, same five cars, same AI, same race
director — running on Lumen, virtual shadow maps and TSR instead of WebGL.

Like the original, **there are no binary assets**. The circuit, terrain, road, bridge,
tunnel, city, forest and every car are generated procedurally when the game starts.
The only authored assets are five master materials and an empty level, and those are
themselves generated by a script.

---

## Running it

Requires **Unreal Engine 5.8** and Xcode (macOS) or Visual Studio (Windows).

**1. Build the code**

```bash
"/Users/Shared/Epic Games/UE_5.8/Engine/Build/BatchFiles/Mac/Build.sh" ApexHorizonEditor Mac Development -Project="$PWD/ApexHorizon.uproject" -waitmutex
```

**2. Generate the materials and the level** — once, before the first run

```bash
"/Users/Shared/Epic Games/UE_5.8/Engine/Binaries/Mac/UnrealEditor-Cmd" "$PWD/ApexHorizon.uproject" -run=pythonscript -script="$PWD/Tools/generate_assets.py" -stdout -unattended -nosplash
```

**3. Play**

```bash
open -a "/Users/Shared/Epic Games/UE_5.8/Engine/Binaries/Mac/UnrealEditor.app" --args "$PWD/ApexHorizon.uproject"
```

Then press **Play** in the editor. First launch compiles shaders, which takes a while;
after that the world builds in a couple of seconds at startup.

If you skip step 2 the project still runs — the material library falls back to engine
materials and logs a warning — but everything will be untextured grey.

## Configuring an event

Everything is read from `Config/DefaultGame.ini` at startup, so races can be
reconfigured without touching code:

```ini
[/Script/ApexHorizon.ApexGameMode]
RivalCount=7                 ; 0–11
Laps=3
Mode=Race                    ; Race | TimeTrial | FreeRoam
PlayerCarId=vulcan           ; kestrel | aurelia | baron | vulcan | mistral
PlayerTyreId=sport           ; street | sport | race | rally
WeatherPreset=Clear          ; Clear | Overcast | Rain | Fog
TimeOfDay=Noon               ; Dawn | Noon | Sunset | Night
bAdvanceTimeDuringRace=False
PropDensity=1.0              ; scales tree and building counts
```

## What carried over, and what changed

### Carried over exactly

- **The circuit.** The same 17 control points through a centripetal Catmull-Rom spline,
  resampled to the same ~3 m spacing, with the same elevation smoothing, gradient
  clamp, banking and width rules. It is the same 4.7 km lap.
- **The world.** Same seeded value-noise terrain function, same hills, same city basin,
  same canyon carve, same mountain ring. Trees, buildings and street furniture come
  from the same seeds and the same placement rules, so the world is laid out the same
  way every run.
- **The cars.** Same five vehicles, same torque curve, gear ratios, final drives,
  masses, drag and downforce coefficients, suspension rates, steering locks and tyre
  compounds. Same upgrade and tune model, same performance-index formula.
- **The AI.** The same pure-pursuit driver: the same pre-computed racing line with
  out-in-out offsets and a two-pass speed profile, the same 240 m lookahead braking
  solver, the same lateral negotiation, the same per-driver skill and imperfection,
  the same stuck-recovery and no-progress watchdog.
- **The race director.** Same continuous-arc-length progress tracking, same 18
  checkpoints, same lap and sector timing, same live placement and gap calculation.

### Changed

- **Physics runs on Chaos** rather than a hand-written raycast vehicle. The source
  data is mapped onto Chaos' engine, transmission, differential, steering and
  suspension configuration — see `ApplyRuntimeTuning` in
  [`ApexVehiclePawn.cpp`](Source/ApexHorizon/Private/ApexVehiclePawn.cpp) for the
  conversions, including how the source's acceleration-per-metre spring stiffness and
  "brakeStrength × 3 g" braking convention become Chaos' units. Surface-aware grip
  (wet tarmac, off-road, compound) is applied per wheel every 50 ms, as before.
- **Lighting is fully dynamic.** Lumen global illumination and reflections, virtual
  shadow maps, a physically-based sky atmosphere with volumetric cloud and fog, real
  spot-light headlights and street lamps, and TSR instead of SMAA. Car paint is a real
  clear-coat material with metallic flake and a pearl fresnel shift.
- **Coordinate system.** The original works in metres in a right-handed, Y-up space.
  All the world-generation maths keeps those units and that convention; `ApexToUE` in
  [`ApexMath.h`](Source/ApexHorizon/Public/ApexMath.h) is the single place it becomes
  Unreal's left-handed, Z-up centimetres.

### Not carried over

- **Audio.** The original synthesises its engine note, tyre screech and wind with the
  Web Audio API. That has no direct equivalent here and would need MetaSounds; the
  project is currently silent.
- **Garage and menus.** Paint, tyres, upgrades and tuning are all modelled in
  `ApexCarData` and applied to the car, but the front-end that let you change them is
  not rebuilt — events are configured through `DefaultGame.ini` instead.
- **Tyre marks, particle effects and body deformation.** Skid marks, smoke, spray and
  the mesh denting on impact are not ported; those want Niagara and a runtime decal
  system.

### Driving Chaos Vehicles without a skeletal mesh

Chaos Vehicles assume a skeletal mesh with a physics asset and named wheel bones. There
is no skeleton here — the chassis is a `UProceduralMeshComponent` built at runtime — so
three things had to give:

1. **`CanCreateVehicle()`** is overridden to drop the bone-name requirement (the base
   class' other checks still run). Wheels are then placed from `AdditionalOffset`, which
   is exactly what `LocateBoneOffset` falls back to when the bone name is `NAME_None`.
2. **Wheel configuration comes from the class default object**, not the instance —
   `SetupVehicle` reads `WheelClass.GetDefaultObject()`. So each car has its own front
   and rear wheel class (`UApexWheelKestrelFront` and friends), each filling its radius,
   width, spring rate, damping and travel from the catalogue. Only build-dependent
   values — tyre grip, brake torque, steering lock — are patched per instance, through
   the runtime setters that are properly bounds-checked.
3. **Components register during `SpawnActorDeferred`**, before `Configure()` runs, so
   Chaos first builds the vehicle from an empty configuration and switches the
   mechanical simulation off. `BeginPlay` calls `RecreatePhysicsState()` to rebuild it
   against the real drivetrain.

One engine-side gotcha worth knowing: `SetSuspensionParams` indexes `ConstraintHandles`
guarded only by the wheel count, so it asserts if the suspension constraints do not
exist yet. Sourcing suspension from the wheel classes avoids it entirely.

## Performance notes

- The world builds in **0.35 s** on an M-series Mac: a 4683 m circuit, 5705 trees, 209
  buildings, across 80 procedural mesh components chunked spatially so frustum culling
  has something to work with. Collision is cooked synchronously during that build,
  because the cars are placed on the grid in the same frame.
- **Runtime-generated geometry has no mesh distance fields**, so software Lumen has
  nothing to trace against and falls back to screen traces plus the sky light. Outdoors
  in daylight that still looks right, because sun and sky dominate; indoors — the
  tunnel — indirect lighting is weaker than it would be with baked meshes. Turning on
  hardware ray tracing fixes this properly, since it traces the real triangle BVH:

  ```ini
  ; Config/DefaultEngine.ini
  r.RayTracing=True
  r.Lumen.HardwareRayTracing=True
  ```

  It is off by default only because enabling it compiles a large extra set of shader
  permutations on first launch.
- Nanite is enabled project-wide but does not apply to procedural meshes.
- Drop `PropDensity` in `DefaultGame.ini` if the forest is costing too much.
